# 《Save The Spire》卡牌系统设计

> 模块：卡牌定义、牌堆、抽牌 / 弃牌 / 消耗、能量费用、效果执行
> 包路径：
> `com.roguelike.dungeon.game.card`
> `com.roguelike.dungeon.game.deck`
> `com.roguelike.dungeon.game.battle`
> Java 版本：21
> 关联文档：`docs/实体接口规范.md`

## 1. 目标

卡牌系统只负责和“打出一张牌”相关的流程，不直接管理玩家和敌人的内部字段。
战斗实体通过 `CardEffectContext` 暴露操作，这样实体层后续实现 `IHealth`、`IArmor`、
`IEnergy` 时，卡牌层不需要跟着重写。

核心规则对齐《杀戮尖塔》：

- 玩家默认每回合 3 点能量，抽 5 张牌。
- 打出卡牌前先做能量校验，能量不足时整次出牌失败，不扣费、不移牌、不执行效果。
- 普通牌执行效果后进入弃牌堆；标记为“消耗”的牌进入消耗堆。
- 玩家结束回合时，剩余手牌全部进入弃牌堆，剩余能量清零。
- 抽牌堆为空时，把弃牌堆洗回抽牌堆。
- 玩家回合开始时清空玩家护甲，并刷新能量；怪物回合开始时清空怪物护甲。

## 2. 类职责

| 类 | 职责 |
| --- | --- |
| `Card` | 一张卡牌的不可变定义：名称、类型、费用、描述、效果、是否消耗、是否可打出 |
| `CardInstance` | 牌堆或手牌中的一张具体卡牌，携带实例 id，用于区分同名卡牌 |
| `CardType` | 卡牌大类：攻击、技能、能力、状态、诅咒 |
| `CardEffect` | 卡牌效果执行接口，新增卡牌只需实现它 |
| `CardEffectContext` | 卡牌效果能调用的战斗操作边界 |
| `CardLibrary` | 当前版本的卡牌定义和起始牌组 |
| `CardPiles` | 抽牌堆、手牌、弃牌堆、消耗堆的容器与移动规则 |
| `Combat` | 战斗流程编排：回合、能量、出牌、怪物行动、胜负判定 |

## 3. 出牌流程

```text
玩家点击手牌
  -> Combat 校验是玩家回合且牌可打出
  -> 校验 energy >= card.cost
  -> 从手牌移除该牌，扣除能量
  -> 执行 card.effect()
  -> 普通牌进入弃牌堆，消耗牌进入消耗堆
  -> 检查战斗是否结束
```

能量不足时，`Combat.playCard` 只记录日志并返回，不改动任何牌堆或战斗状态。

## 4. 牌堆规则

`CardPiles` 同时维护四个区域：

- 抽牌堆 `drawPile`
- 手牌 `hand`
- 弃牌堆 `discardPile`
- 消耗堆 `exhaustPile`

抽牌规则：

- `draw(count)` 每次从抽牌堆顶部取牌。
- 抽牌堆为空且弃牌堆非空时，先把弃牌堆全部洗回抽牌堆。
- 抽牌堆和弃牌堆都为空时，停止抽牌，本次抽牌张数可能少于请求值。
- 出牌后普通牌放回弃牌堆，所以卡牌自身的抽牌效果不会把刚打出的牌抽回来。

## 5. 卡牌扩展方式

新增卡牌只需要三步：

1. 在 `CardLibrary` 中定义 `Card`。
2. 用 lambda 或类实现 `CardEffect`。
3. 将卡牌加入某个牌组或奖励池。

例如：

```java
public static final Card IRON_WAVE = new Card(
        "iron_wave",
        "铁斩波",
        CardType.ATTACK,
        1,
        "造成 5 点伤害，获得 5 点护甲。",
        context -> {
            context.dealDamageToMonster(5);
            context.addPlayerBlock(5);
        },
        false,
        true);
```

后续加入易伤、虚弱、力量等状态时，优先扩展 `CardEffectContext`，而不是让卡牌直接
修改 `Combat` 的私有字段。

## 6. 当前起始牌组

当前基础牌组保持 10 张，与 MVP 平衡接近：

- 5 张 `打击`：1 费，造成 6 点伤害。
- 5 张 `防御`：1 费，获得 5 点护甲。

`CardLibrary` 同时准备了若干扩展卡牌用于验证效果执行器，暂未加入起始牌组：
痛击、快斩、重击、铁斩波、耸肩、放血。
