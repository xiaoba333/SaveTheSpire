# 多敌人目标选择 — 修复方案

> 模块：战斗与怪物 AI（战斗负责人）
> 范围：`game.battle` / `game.enemy` / `http` / `ui.battle`
> 状态：**已实现并验证**（全量 148 个单测 + 47 项多敌人冒烟断言全绿）

---

## 一、问题定位

需求是「有些关卡会有多个敌人，玩家要能选择打哪一只」。改造前的情况是：
**数据层已经支持多怪，但上三层全部把它丢掉了**，所以多怪编队从来没有真正出场过。

| 层 | 位置 | 改造前状态 |
|----|------|-----------|
| 遭遇定义 | `EncounterDefinition` | ✅ `spawns` 是 List，带 `variant`，已注册 `act1_grubs`（两条蛆）与 `act1_explorers`（探险者二人组） |
| 按节点挑选 | `GameController.pickMonster` | ❌ 只调 `MonsterCatalog.randomEasy/elite/boss`，返回单只 `MonsterAi`，编队信息在入口被丢弃；`createMonsters()` 的生产调用方只有 demo |
| 战斗运行时 | `BattleState` | ❌ 单 `monsterHp` / `monsterBlock` / `livingMonster` 字段；`applyDamage(boolean, int)` 无目标参数 |
| 卡牌结算 | `CardEffectContext` | ❌ `dealDamageToMonster(int)` 无目标参数；`dealDamageToAllMonsters` 注释直写「当前单敌人模型下等价于攻击当前敌人」 |
| 怪物 AI | `ScriptedMonsterAi` | ❌ `allMonsters()` 只返回自己，`allies()` 恒空 → `giveAllyBlock` / `buffAlliesStrength` 静默失效 |
| 界面 | `BattleView` | ❌ 单个 `monsterView`，「把牌拖向怪物」（单数） |

**命名陷阱**：全项目已有的 `target*` 参数指的都是「锻造靶手牌」（`targetCardId`），
**不是敌人目标**，改动时不要与它混用。

---

## 二、实现思路

核心取舍：**加一条编队路径，而不是把单怪路径改造成多怪路径。**

- `BattleState` 同时支持「名册模式」（`List<Monster>`）与「木桩模式」（单整数血量）。
- 名册为空时行为与改造前**逐字节一致**，`DefaultMonsterAi` 与大量卡牌单测继续走这条路径。
- 名册非空时，单目标操作统一落在**当前锁定目标**身上。

这样做的收益是改动可灰度、可回滚，且不需要一次性重写 28 个测试类。

### 数据流

```
EncounterCatalog (act1_grubs / act1_explorers)
        │  createMonsters()
        ▼
MonsterEncounterAi ──bindMonsters()──▶ BattleState.monsters + targetIndex
        │                                        │
        │ takeTurn() 逐只行动                     │ applyDamageToMonster(target, n)
        ▼                                        ▼
   BattleContext                        CombatCardEffectContext
   allMonsters()/allies()/findAlly()     dealDamageToMonster() → 锁定目标
   ← 真实名册，友方技能生效                dealDamageToAllMonsters() → 全部存活怪
```

## 四、关键设计决策（请战斗负责人复核）

### 1. 目标阵亡后自动转向下一个存活者

`applyDamageToMonster` 结算后会调 `retargetIfNeeded()`：锁定目标死亡则自动切到第一只存活怪，
后续单目标伤害不再打进尸体。

这与杀戮尖塔一致（打死当前目标后，剩余攻击自动转向下一个敌人），避免玩家因为「忘了切目标」白扔伤害。
冒烟测试第 3、4 节专门验证了这条。

### 2. 每只怪各自持有一份战斗状态

易伤 / 虚弱 / 中毒 / 血畜等**战斗向**状态按怪物实例分别存放（身份比较索引），
`tickMonsterStatuses()` 逐个结算。"血畜"在**全灭时按全场累计**一次性补最大生命。

> ⚠️ 注意：`Monster` 继承了 `Enemy` 的实体级状态表（`game.entity.StatusEffect`），
> 与战斗向状态表（`game.enemy.status`）是**两套不同的东西**，改造时刻意没有合并。
> 合并会让易伤在 `BattleState.applyDamage` 和 `Enemy.receiveDamage` 里**各乘一次 1.5**，
> 属于隐藏的数值事故，不在本次范围内。

### 3. 探险者站位顺序必须改（本次唯一的数值/数据改动）

`act1_explorers` 原本是 `[探险者男, 探险者女]`，但 `Monster.onTurnStart` 会清空**自己**的护甲：

```
男.onTurnStart → 男行动(给女 +10 甲) → 女.onTurnStart(清空自己的护甲!) → 女行动
                                       ↑ 刚给的 10 甲当场蒸发
```

结果是「男给女上 10 甲」这条协作机制**永远看不到效果**。
改成 `[探险者女, 探险者男]`（女先动、男后动）后，男的护甲留到玩家回合，
玩家必须决定先杀谁 —— 这才是设计案里写的意图。

> 已生效验证：一回合后 `探险者女 甲10`，日志出现「探险者男 给 探险者女 上 10 点护甲」。
> 如果更希望保持「男在前」的站位，替代方案是让怪物阶段开始时**统一清一次全体护甲**
> 而不是每只怪各自清，但那会改动 `Monster.onTurnStart` 的既有语义，影响面更大，本次未采用。

### 4. 兼容性：木桩模式原样保留

`BattleState` 名册为空时仍走原来的整数血量 + 单状态表逻辑。
`DefaultMonsterAi`、`CombatTest`、`BattleStateTest`、`CardPlayServiceTest` 等**全部未修改**且全绿。

## 五、HTTP 契约变更（`docs/http-api.md` 已同步）

**新增端点**

```
POST /api/v1/battles/{battleId}/target
请求体：{ "index": 1 }        // 或 { "monsterId": "explorer_female" }
响应 200：BattleState
响应 400：INVALID_TARGET（目标不存在 / 已阵亡）
```

**扩展请求体**

```
POST /api/v1/battles           { "encounterId": "act1_grubs" }        // 可选，直接开指定编队
POST /api/v1/battles/{id}/play { "cardId": "...", "targetIndex": 1 }  // 可选，先切目标再出牌
```

**扩展响应字段**（`enemies[]` 内新增，向后兼容）

| 字段 | 类型 | 说明 |
|------|------|------|
| `index` | int | 敌人下标，即 `selectTarget` / `targetIndex` 用的值 |
| `name` | string | 敌人显示名 |
| `strength` | int | 当前力量（含状态加成） |
| `alive` | bool | 是否存活 |
| `targeted` | bool | 是否为玩家当前锁定的目标 |

**新错误码**：`INVALID_TARGET`

## 七、回归风险与已知取舍

| 风险 | 说明 | 处置 |
|------|------|------|
| 普通战斗难度曲线变化 | 普通节点现在会抽到 2 怪编队（约 29% 概率） | 需要一次数值试玩；不想要就改回 `MonsterCatalog.randomEasy(seed)` |
| 日志文案变化 | 从「骷髅发动攻击（打6）」变为「骷髅 行动：攻击」，丢失脚本原文案 | 仅影响可读性；如需原文案可给 `MonsterAi` 加 `intentTextFor(monster)` |
| UI 动画只跟随锁定目标 | 大立绘仍是一只，不是并排 N 只 | 本次为控制风险未重做战斗场景布局；多怪时用顶部选择条区分 |
| Boss 仍是单怪 | 凯洛斯的形态变换与多怪槽位未做耦合测试 | 刻意保持，避免同时引入两个变量 |
| 属性缩放未做 | 多怪没有像杀戮尖塔那样按数量削血 | 属平衡工作，不在本次范围 |
