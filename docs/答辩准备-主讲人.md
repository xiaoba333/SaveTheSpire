## 3. 中间 4 分钟：关键设计决策（主讲核心）

只讲 **3 个决策**。每个约 70–80 秒：问题 → 选择 → 证据（类名 / 测试名）。

### 决策 A：后端权威 + 流程状态机（约 80 秒）

**问题：** 如果 UI 自己改血量、金币、牌组，客户端和服务器会各算各的。

**选择：**

- 跨关卡权威在 `RunState`（玩家、永久牌组、金币、章节、地图）。  
- 局内阶段在 `GameController` + `GamePhase`：`MAP / BATTLE / REWARD / EVENT / SHOP / REST / VICTORY / DEFEAT`。  
- 战斗内另有子状态：玩家回合 → 结束回合 → 怪物行动 → `checkFinished`。  
- HTTP 约定：每次操作返回完整 `BattleState`，Unity 只刷新，不算伤。

**为什么不是一个大枚举装所有状态：** 菜单（选角）和局内（地图/战斗）生命周期不同，拆成 `MenuPhase` 和 `GamePhase`，避免「还没开局却能结束回合」这种死状态。

**证据：** `docs/Day04-详细设计说明书.md` 第 1 节状态转移表；`GameController.selectNode` 按节点类型穷尽分支。

### 决策 B：把上帝类 Combat 拆开（约 80 秒）——这是「最难」候选

**问题：** 早期 `Combat` 同时管数据、出牌、怪物行动、胜负、日志，改一处全断。

**选择：**

| 类 | 职责 | 明确不做什么 |
| --- | --- | --- |
| `BattleState` | 血量、能量、牌堆、状态层数 | 不管回合顺序 |
| `CardPlayService` | 扣费、执行卡牌效果 | 不判定胜负、不引用 `Combat` |
| `MonsterAi` | 意图与行动 | 只碰 `BattleState` / `BattleContext` |
| `Combat` | 只调度回合 | 成功出牌后才 `checkFinished()` |
| `BattleEventBus` | 结束通知 | 只发布一次 |

**最难的点：** AI 初稿让 `CardPlayService` 返回 `Combat` 内部枚举，形成 `CardPlayService → Combat → CardPlayService` 循环依赖。

**原理一句话（评委爱听的「算法级」回答）：**  
把结果类型提升为顶层 `PlayCardResult`。出牌失败在服务层返回，调度器不改状态；只有 `SUCCESS` 才检查 HP。这和「先算再提交、失败回滚」是同一类边界。

**证据：** `CombatTest`、`CardPlayServiceTest`、`BattleEventBusTest`。

### 决策 C：怪物 AI 与战斗解耦；Boss 蛋链是规则不是 UI（约 80 秒）

**问题：** Boss 有五段（无暇 → 轻微破裂 → 中度破裂 → 几乎破裂 → 凯洛斯）。若「HP≤0 就胜利」，打死第一段蛋会直接通关。

**选择：**

- 图鉴脚本在 `ActOneBestiary`，战斗侧用 `ScriptedMonsterAi` 接到 1v1 `Combat`。  
- 蛋自己回合执行「破裂」才 `transform` 并 **蜕变 +1**。  
- 玩家把蛋打碎：换下一形态，**蜕变不加**（早点打蛋，本体力量更低）。  
- 雇佣兵事件：付 50 金，进入「几乎破裂」时直接切到本体，**也不加蜕变**。

**原理一句话：**  
蜕变层数记在 `ScriptedMonsterAi` 上，不跟即将销毁的蛋实例走。自己破裂才 `metamorphosisStacks++`；玩家击杀和雇佣兵砸碎只 `transform` + 重挂已有层数。本体出场时把层数写成力量。

**证据：** `MonsterAiTest.killingBossEggAdvancesToNextPhaseInsteadOfWinning`、`fourEggRupturesConvertMetamorphosisIntoKairosStrength`、`hiredMercenarySkipsAlmostCrackedEggPhase`。

讲完这 3 个决策，用 10 秒过渡：

> 「规则能测，是因为效果都在后端。下面 2 分钟讲我们怎么测、怎么用 AI。」

### 6.1 预判问题（主讲人必答）

**Q：为什么 UI 不算伤害？**  
A：防止双端不一致。`CardEffectContext` 只对战斗状态写，HTTP 每次回完整快照。

**Q：能量不足时为什么说「整次失败」？**  
A：`CardPlayService` 先校验再扣费执行。失败返回枚举，HP、能量、手牌都不变。

**Q：易伤什么时候掉层？**  
A：玩家点结束回合后，**先** `player.tickEndOfTurn()`，**再**怪物行动，**再** `tickMonsterStatuses()`。所以你这回合给怪上的易伤，本回合输出还在。

**Q：AI 写了哪些代码？你怎么知道是对的？**  
A：用第 4.2 节表格。强调「原理 + 测试名 + 我们改了循环依赖」。

**Q：Boss 打死一阶段为什么以前会胜利？**  
A：`checkFinished` 把 `monsterHp<=0` 当成整场结束。现在先 `onHpDepleted`，有下一形态就变形。

**Q：地图层数为什么改 14？**  
A：生成器常量 `MapGenerator.FLOOR_COUNT`。第 0 层仍是战斗，倒数第二层休息，顶层 Boss。测试按常量断言，不用改死数字。

## 12. 互评表怎么写才不像敷衍

每人至少三句，必须能核对仓库：

- 「XX 负责 `GameController` 阶段守卫，我走查时指出商店退出边，后来补了 `leaveShop`。」  
- 「XX 写了 `EventCatalog` 雇佣兵，我用 `EventServiceTest` 复现了金币不足不可选。」  
- 「XX 接 Unity HTTP，对照 `docs/http-api.md` 把 `phase` 和 `cardId` 对上了。」

禁止：负责、积极、沟通顺畅（无文件名、无测试名）。
