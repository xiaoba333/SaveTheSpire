# 遗物设计案（扩充）

> 范围：在现有收录基础上扩增一批遗物，并按 **Boss 遗物 / 普通遗物** 分开设计。
> 落地文件：`src/main/java/com/roguelike/dungeon/game/relic/`。
> 数值基准：玩家 50 生命 / 3 能量；打击约 6 伤害、防御约 6 护甲；怪物 12–150 血。

---

## 一、现状盘点

现有收录 **18 件**（`game.relic.RelicLibrary`）：

| 稀有度 | 数量 | 明细 |
| --- | --- | --- |
| 普通 | 8 | 船锚、心之石、绷带（初始三件）+ 磨刀石、麻醉剂、荆棘之甲、记账本、重锤 |
| 罕见 | 4 | 血之代价（初始）+ 苦无、手里剑、放血槽 |
| 稀有 | 5 | 钙化壳、处刑者、不死鸟之羽、玻璃大炮、贪婪之杯 |
| Boss | **1** | 黑暗契约 |

### 现有系统的两个硬伤

**1）Boss 遗物没有任何产出路径，黑暗契约永远拿不到。**

`GameController.relicRaritiesFor()` 只提供两种池子：

```java
ELITE → {COMMON, UNCOMMON, RARE}
其他  → {COMMON, UNCOMMON}
```

`BOSS` 稀有度既不在普通池也不在精英池；而 `finishBattle()` 在 Boss 节点胜利后直接
`return`（进入下一层或通关），**不发奖励**。也就是说 BOSS 稀有度目前是一段死代码。

**2）「每回合额外获得能量」这类遗物在现有 API 下实现不了。**

`Player.refresh()` 会把能量直接设为 `maxEnergy`，`Player.addEnergy()` 又 `clamp` 到
`maxEnergy`。而 `RelicTrigger.TURN_START` 的触发时机是「清空护甲、**刷新能量之后**」——
此时能量已经等于上限，再加也加不上去。所以每回合加能量的设计**必须**改成
「永久提升能量上限」（只能在 `OBTAIN` 时机做）。本设计案已按这个约束回避。

> 若后续确实要出「每回合 +1 能量但只能本回合用」的遗物，需要给 `Player` 加一个
> `gainBonusEnergy(int)`（允许突破上限），约 5 行代码。本批次不引入该改动。

---

## 二、设计原则

1. **只用现有触发点与 API**，不新增钩子。可用触发点 9 个：
   `OBTAIN / BATTLE_START / TURN_START / TURN_END / CARD_PLAYED / DAMAGE_DEALT / DAMAGE_TAKEN / ENEMY_KILLED / BATTLE_END`。
2. **每件遗物只解决一个决策问题**，不做「什么都加一点」的复合体。
3. **稀有度对应强度**：普通 ≈ 每回合 2–3 点稳定收益；罕见 ≈ 条件性收益或小代价换收益；
   稀有 ≈ 全局 35–50% 增幅或构筑核心；Boss ≈ 定义打法并附带明确代价。
4. **Boss 遗物必须有代价**，且代价要落在「另一种资源」上（生命 / 输出 / 承伤 / 成长节奏），
   这样三选一才是真选择而不是「选最强的」。

## 三、普通遗物扩充（13 件）

### 3.1 普通 COMMON（+5）

| ID | 名称 | 触发点 | 效果 | 设计意图 |
| --- | --- | --- | --- | --- |
| `iron_will` | 铁誓 | TURN_START | 每回合开始时获得 3 点护甲 | 稳定续航，与「船锚」（一次性 8 甲）形成「长期 vs 短期」取舍 |
| `scavenger` | 拾荒者 | ENEMY_KILLED | 击杀怪物时回复 2 生命并获得 5 护甲 | 给「斩杀」正反馈；注意当前实战为 1v1，触发频率天然受限，故数值给得比同类高 |
| `steady_hands` | 沉稳之手 | CARD_PLAYED | 每回合打出的第 1 张牌使你获得 2 点护甲 | 奖励「先出低费牌铺垫」的出牌顺序，而不是无脑先甩大招 |
| `momentum` | 惯性 | CARD_PLAYED | 每累计打出 5 张牌，造成 3 点无视护甲伤害 | 给「多抽牌/低费流」一条稳定输出线，与苦无（攻击牌 3 张 → 2 甲）互补 |
| `second_wind` | 回气 | TURN_END | 回合结束时若能量为 0，获得 3 点护甲 | 把「能量刚好用完」变成收益，缓解新手「能量剩 1 点花不掉」的挫败 |

| --- | --- | --- | --- | --- |
| `juggernaut` | 势不可挡 | TURN_END | 造成等于你当前护甲 50% 的无视护甲伤害 | 「叠甲流」的收束件：把纯防御资源转成输出，让防御牌不再只是挨打 |

## 四、Boss 遗物扩充（6 件）

Boss 遗物与普通遗物**分开建池**：不进任何常规掉落池，只在 Boss 战胜利后三选一。
一局最多拿一件（`bossChoices` 会排除已持有的）。

| ID | 名称 | 触发点 | 效果 | 代价落在哪 | 打法定位 |
| --- | --- | --- | --- | --- | --- |
| `dark_pact` | 黑暗契约 | OBTAIN | 能量上限 +1，最大生命 −12 | 生命上限 | 资源型（*现有*） |
| `crimson_crown` | 猩红王冠 | DAMAGE_DEALT + BATTLE_START | 你造成的伤害 +35%；每场战斗开始时失去 20% 当前生命 | 每战当前生命 | 爆发型：短战越猛，长线越危险 |
| `leviathan_heart` | 利维坦之心 | OBTAIN + TURN_END | 获得时最大生命 +30 并回满生命；每回合结束时失去 2 生命 | 每回合生命（无视护甲） | 血池型：血上限极高，但被 DoT 持续侵蚀 |
| `aegis_of_ruin` | 废墟之盾 | TURN_START + DAMAGE_DEALT | 每回合开始获得 6 点护甲；你造成的伤害 −20% | 输出 | 防御型：稳定的甲，换掉两成伤害 |
| `soulbound_ledger` | 缚魂账簿 | BATTLE_START + BATTLE_END | 每场战斗胜利后最大生命 +5；每场战斗开始时最大生命 −2 | 开场血上限 | 成长型：净 +3/战，拖得越久越强，但前期更脆 |
| `doomsday_clock` | 末日之钟 | DAMAGE_DEALT | 每第 3 个回合伤害 ×2，其余回合 ×0.6 | 平均输出降低 | 节奏型：把输出压缩到特定回合，要求玩家围绕它排回合 |

### Boss 遗物池的构成逻辑

六个选项刻意落在六个互不重叠的维度上——**资源 / 爆发 / 血池 / 防御 / 成长 / 节奏**，
保证三选一里任意两个都不是「强度高低」而是「打法不同」。同时每件都有清晰代价，
不存在无脑最强项：

- 拿 `crimson_crown` 就得接受「打完这场只剩八成血进场」；
- 拿 `leviathan_heart` 就得接受每回合固定掉 2 血，血上限再高也可能被磨死；
- 拿 `doomsday_clock` 就得接受 2/3 的回合输出打六折，把爆发压在每第 3 回合。

## 五、产出路径：Boss 遗物怎么发

新增 `RelicLibrary.bossChoices(seed, player, count)`：从尚未持有的 Boss 遗物里按种子洗牌取 N 件，
**只选不发**（不选中的候选零副作用），实际获得仍走 `RelicService.acquire`，与其他遗物完全一致。

流程侧只需要在 `GameController.finishBattle()` 的 Boss 分支里接一次：

```java
MapNode node = requireCurrentNode();
if (node.type() == MapNodeType.BOSS) {
    currentCombat = null;

    // ↓ 新增：Boss 战胜利 → 三选一 Boss 遗物
    List<Relic> choices = RelicLibrary.bossChoices(
            rewardSeed(node), runState.getPlayer(), 3);
    // 交给现有的奖励界面展示；玩家选中后 relicService.acquire(选中的那件)
    currentReward = RewardService.forBossRelicChoice(...);

    getMapService().completeCurrentNode();
    ...
}
```

> 这一段涉及 `flow` 与 `RewardService`，属于流程模块的改动范围，因此本批次**只提供
> `bossChoices` 接口与接法**，没有直接改 `GameController`。Boss 遗物在流程接上之前
> 处于「已注册但暂不可得」状态——与现状相比是前进（现状是连池子都没有），
> 但**必须接上这一步才算真正交付**。

## 八、待办与风险

1. **Boss 奖励未接线**（见第五节）：优先级最高，不接就等于这批 Boss 遗物白设计。
2. **数值待实测**：`soul_harvest`（跨战斗 +3 血）与 `predators_ferocity`（力量叠加）
   都有滚雪球属性，长局可能超模。建议观测量：通关时玩家最大生命、力量层数。
3. **两处重名类**（与遗物相关）：`game.entity.RelicLibrary`（只有 2 件，旧）与
   `game.relic.RelicLibrary`（36 件，实际在用）同名共存，`import` 写错就静默取到旧表。
   建议把 `game.entity.RelicLibrary` 合并进来并删除。
4. **`doomsday_clock` 依赖 `battle.turnNumber()`**：若后续回合计数口径变化（例如跨战斗累计），
   该遗物的「每第 3 回合」会随之改变，改动时需一并确认。
